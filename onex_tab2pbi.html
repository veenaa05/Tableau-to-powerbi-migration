Onex tab2pbi

Onex tab2pbi converts a Tableau workbook (.twb or .twbx) into a Power BI Project (PBIP): the semantic model as TMDL and the report as PBIR, the open formats Power BI Desktop and Microsoft Fabric read directly. Every datasource, field, calculation, parameter, worksheet and dashboard object it touches is listed in a migration report with a status, a reason and the original Tableau definition, so nothing is dropped silently and the remaining work is known up front.

Application architecture

A command-line application in Python with five stages. The stages only meet through a tool-neutral intermediate model, so the Tableau reader and the Power BI writers never depend on each other, and every converter returns its output together with a report entry for each item it handled.

InputTableau workbook .twb / packaged .twbx with its data files and images; optional --data-dir with the source files
↓
1 · ParseUnzips the package and reads the workbook XML: datasources, joins, calculations, parameters, worksheets, dashboards, actionsparser/
2 · Intermediate modelTyped, tool-neutral description of both sides (Tableau and Power BI) plus the migration itemsir/
3 · ConvertPower Query M and relationships, Tableau formulas to DAX (parser → syntax tree → rules → DAX syntax check), parameters, visuals, filters, layout, actionsconvert/
↓
4 · EmitPower BI Project: .pbip, .SemanticModel (TMDL), .Report (PBIR JSON validated against Microsoft's published schemas), images and bookmarksemit/
5 · Migration reportHTML, Markdown and JSON: every item with status, reason, original definition, Power BI target and an effort estimatereport/
Optional AI assistPluggable translator for calculations the rules can't convert. Off by default; answers must pass the DAX checks and stay flagged for reviewllm/

Quality controls

  • Deterministic rules first; nothing is guessed, and table calculations are never approximated.
  • Every generated DAX expression passes a syntax check before it is written.
  • Every report file validates against Microsoft's JSON schemas.
  • Repeatable output: the same workbook always produces identical files.
  • Automated tests for every rule, plus sample projects opened, refreshed and value-checked in Power BI Desktop.

Security

  • Credentials are never read or copied; Power BI Desktop asks for them on first refresh.
  • Only files packaged in the workbook or handed over with --data-dir are read, never other paths a workbook names, and never network paths.
  • Size limits on every file read, including Excel parts.
  • Runs locally; no data leaves the machine unless the optional AI assist is configured.

How to read a status

Each item in the migration report gets exactly one of three statuses. Nothing is meant to be dropped silently: if tab2pbi skips something, the report says so.

CONVERTED

Deterministic rule with an equivalent result in Power BI. No action needed beyond a normal review.

APPROXIMATED

Converted, but behaviour can differ in a known way (filter context, week starts, join semantics). The report names the difference. Check these.

MANUAL

No faithful rule. A placeholder keeps the model and page loadable (a BLANK() measure, an empty typed table or a text box), and the original definition is kept so someone can rebuild it.

What needs a manual check

After a conversion, this is the checklist. Most of it is driven by the MANUAL and APPROXIMATED lines in migration_report.md, so each item is pinned to the field, page or table it concerns.

Repoint data files, refresh and sign in

The project has no data cache. Convert with --data-dir <folder with the CSV/Excel files> so file queries point at the real files (in the proof of concept every datasource referenced the author's machine); otherwise change them in Transform data → Data source settings. Then Home → Refresh, enter database credentials, approve native (custom SQL) queries, and save (Ctrl+S): a refreshed project that isn't saved opens empty again, with "(Blank)" cards.

every project

Rebuild table calculations

Find measures in the _Needs manual conversion folder. Each holds the Tableau formula and a suggested DAX approach in comments; most map to visual calculations or WINDOW / OFFSET / RANKX.

calculations · MANUAL

Check LOD results against Tableau

FIXED ignores report filters in the DAX version. Compare a few numbers with the Tableau view, especially with filters applied and on totals.

calculations · APPROXIMATED

Confirm relationships

Check assumed many-to-one directions, decide whether former inner joins should hide unmatched rows, and turn on inactive relationships where a calculation needs them.

relationships

Replace placeholder queries

Tables from unsupported connectors are empty with the right columns. Rewrite their Power Query against the real source; everything built on them starts working.

datasources · MANUAL

Rebuild unconverted visuals

A text box marks each one, at the Tableau position. Pick the Power BI visual and drag the fields in; the report line lists the original shelves.

worksheets · MANUAL

Tune slicers and interactions

Set parameter slicers to single select. Use Edit interactions so filter-card slicers only affect the visuals the Tableau filter applied to.

dashboard zones

Check charts that look empty or flat

A chart built on a table-calculation placeholder renders empty (for example running minimum / maximum lines). A scatter that plotted every row in Tableau shows one point per legend value: add the ID column to Details. Replace <[Parameters].[...]> text in titles, and upgrade map visuals to Azure Maps when Desktop asks.

visuals · after refresh

Recreate the rest of the interactivity and styling

Go-to-sheet actions, parameter and set actions, wildcard and formula filters, manual sort orders, colors, fonts, tooltips and reference lines are done in Desktop for now. Several are on the roadmap below.

not converted

What will not be converted

No Power BI equivalent

  • R and Python script calculations (SCRIPT_*)
  • Stories as a storytelling format (each story point could become a bookmark at best)
  • Tableau's exact join row semantics inside one table
  • .hyper extract contents (the source is queried instead)

Out of scope by decision

  • Row-level security and user filters
  • Themes and custom formatting
  • Tableau Server published datasources
  • Credentials (never copied; Desktop always asks)
  • Guessing table calculations. They stay MANUAL even with the optional LLM path.

Running it

pip install -e .
tab2pbi convert samples/simple_bar.twbx --out out/simple_bar
# open out/simple_bar/simple_bar.pbip in Power BI Desktop, then Home → Refresh
# open out/simple_bar/migration_report.html in a browser for the per-item status list

# dry run: only the migration report, no Power BI files
tab2pbi convert my_workbook.twbx --out out/assess --report-only

# point file queries at a local copy of the data, so Refresh works right away
tab2pbi convert my_workbook.twbx --out out/my_workbook --data-dir D:/Data/tableau-files

Output: a .pbip file, a .SemanticModel folder (TMDL), a .Report folder (PBIR JSON validated against Microsoft's schemas), and the migration report as HTML, Markdown and JSON, with counts by type and status and a rough effort estimate. Files are UTF-8 without BOM and output is deterministic, so re-running gives identical files.
